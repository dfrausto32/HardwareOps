# Pre-Apply Demo (Start → Finish)

Canonical deployment and operations flows: `deploy.md`, `operations.md`  
Use this file only for the pre-apply demo scenario.

This walkthrough shows how to demo the **pre-apply hook** live with the UI and the demo agent.

## Prereqs
- Docker + Docker Compose
- Go
- Node.js 18+

## 1) Start dependencies + control-plane
```bash
make dev-up
./scripts/run-control-plane.sh
```

## 2) Start the UI
```bash
cd ui
npm install
npm run dev
```
Open: `http://localhost:5173/`

If you are in realistic TLS mode, make sure the dev CA is trusted and CORS is configured:
```bash
export CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

## 3) Start the demo agent (live web service)
```bash
./scripts/run-demo-agent.sh
```
Open the demo service page:
```
http://localhost:8081/index.html
```

## 4) Build + upload artifacts with pre-apply
Option A (demo v1 → v2 page flip):
```bash
./scripts/demo-artifacts.sh
```

Option B (all artifact types with pre-apply):
```bash
./scripts/artifact-types.sh
```

## 5) Apply from the UI
1. In the UI, select the demo device.
2. Choose an artifact and **Apply**.
3. Watch the demo page update.

## What you should see
- The demo page shows **“Pre‑apply”** content pulled from `files/preapply.txt`.
- The UI dashboard displays a **Pre‑apply badge** with the last status.

## Expected UI/output per artifact type
All artifact types generated by `./scripts/artifact-types.sh` render a page with:
- **Type** and **Version** visible on the page.
- **Pre‑apply** line populated from `files/preapply.txt` (includes type, version, timestamp).

> Note: `firmware` and `container_image` only apply in demo mode because
> `run-demo-agent.sh` sets `ALLOW_UNSUPPORTED_APPLY=1` by default.
> If you disable that flag, those types will fail to apply and the page will not change.

### First apply (per type)
When you apply the first artifact for a type, the page should show:

| Artifact type | Expected page change (first apply) |
| --- | --- |
| `app_bundle` | **Type:** app_bundle, **Version:** `0.1.0-app_bundle` |
| `config_bundle` | **Type:** config_bundle, **Version:** `0.1.0-config_bundle` |
| `data_bundle` | **Type:** data_bundle, **Version:** `0.1.0-data_bundle` |
| `firmware` | **Type:** firmware, **Version:** `0.1.0-firmware` |
| `container_image` | **Type:** container_image, **Version:** `0.1.0-container_image` |

The **Pre‑apply** line will show something like:
```
preapply ok
type=<type>
version=<version>
time=<timestamp>
```

### Update to newest version (same type)
When you update to the newest version for the **same** type, only the **Version**
and **Pre‑apply** timestamp should change:

| Artifact type | Expected page change (update to newest) |
| --- | --- |
| `app_bundle` | **Version:** `0.2.0-app_bundle` |
| `config_bundle` | **Version:** `0.2.0-config_bundle` |
| `data_bundle` | **Version:** `0.2.0-data_bundle` |
| `firmware` | **Version:** `0.2.0-firmware` |
| `container_image` | **Version:** `0.2.0-container_image` |

### Switch between types
When you switch from one type to another (e.g., `app_bundle` → `firmware`):
- **Type** changes to the new type.
- **Version** updates to the selected artifact version (e.g., `0.1.0-firmware`).
- **Pre‑apply** line updates with the new type/version + fresh timestamp.

If the switch does **not** update the page, check:
- Desired state set to the selected artifact,
- `ALLOW_UNSUPPORTED_APPLY=1` if using `firmware`/`container_image`.

## Optional: multiple agents
```bash
DEMO_COUNT=3 DEMO_HTTP_PORT=8081 ./scripts/run-demo-agent.sh
```
Ports: 8081, 8082, 8083

## Troubleshooting
- If the demo page doesn’t update, verify the desired state was set for the device.
- If you’re using HTTPS, ensure the dev CA is trusted or use the proxy in UI dev mode.
